# UI 走查发现（2026-09-18）

用户提供的截图确认了当前后台存在高优先级的响应式和排版问题。窄列布局中，数据卡片标题、指标值与说明文字发生逐字换行，导致“待活动结束”“数据口径”“核验通过”“订单支付成功”等正常语义被拆解为单字纵排。该问题不能通过把词语任意拆分来处理，应通过设置卡片最小宽度、改用横向滚动表格、在指定断点切换为单列布局，以及为中文标题设定语义化断行规则解决。

数据页截图还显示四张统计卡在窄宽度下仍被强制并排，造成金额、比率和说明的层级被挤压；信息应在中小屏切换为 2 列或 1 列，并保持数值与单位在同一行。空白截图显示存在只有分隔线而没有说明和下一步动作的空页面，需统一替换为包含原因、辅助说明与明确操作按钮的空状态。

登录页角色标题的正确规则：完整身份名必须保持为一个语义单元，允许在整个词组之间断行，但禁止把“平台运营人员”“主办方活动运营人员”“文旅业务指导人员”“现场协同人员”中的词语拆成单字或割裂“人员”。说明文案可按短语断行，例如“配置活动流程、账号权限、服务运营”保持一行或按逗号后的短语分行。

# 第二轮问题确认（2026-09-18）

## 语义断行（P1）

截图确认当前主体档案页仍有四类不可接受的换行：

| 原文 | 当前错误 | 修复规则 |
|---|---|---|
| 主办方主体资料 | “资料”被单独落到第二行 | 标题作为完整短语，采用 `white-space: nowrap`；空间不足时先扩宽模块或改为单列 |
| 有效期至 2027-06-09 | 日期被拆为“2027-06- / 09” | 日期、编号、金额作为不可拆分 token，使用 `whitespace-nowrap` 与 `tabular-nums` |

## 操作流（P1）

“查看”弹窗只展示了操作用途和“确认”，没有给出下一步页面、可编辑字段或流程状态，属于虚假交互。每个“查看 / 管理 / 补充”入口应打开一个真实的三段式任务流：**查看当前资料 → 补充或编辑 → 提交并写入记录**。弹窗需要显示当前完成度、材料清单、下一步主按钮和明确的返回路径。

## 视觉语言（P2）

当前横向大号“收起菜单”按钮、图标容器和过大的白色确认弹窗显得像通用生成模板。重构方向：采用克制的信息架构风格，浅暖灰背景、深墨文本、单一沉稳蓝作为操作色、8px 量级圆角、细线分隔、无渐变光晕；将侧栏收起改为紧凑图标按钮并使用 tooltip；将操作弹窗改为任务抽屉/步骤面板，而非泛化的确认框。

## 视觉与操作流复核

主办方说明截图中的换行本身不是错误：第一行完整表述了主体档案的用途，第二行完整表述“不替代审批或登记程序”。应保留这种以语义单元为边界的自然换行，而非强行塞回一行。

“查看”确认弹窗需要被替换为一条可操作的任务抽屉：顶部为当前任务和完成进度，中部展示可查看的材料行与操作记录，底部是明确的“下一步：补充材料 / 保存并返回 / 提交资料”等动作。用户点击“查看”后必须进入操作上下文，而非仅确认一个说明句。

侧边栏收起控件应从横向大按钮改为与折叠栏宽度相匹配的 32px 图标按钮，文本只通过悬浮提示展示。移除泛用的浅蓝图标大方块、厚阴影和超大圆角弹窗，改为细线、紧凑任务面板和真实状态颜色。
