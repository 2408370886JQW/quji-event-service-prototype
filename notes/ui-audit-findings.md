# UI 走查发现（2026-09-18）

用户提供的截图确认了当前后台存在高优先级的响应式和排版问题。窄列布局中，数据卡片标题、指标值与说明文字发生逐字换行，导致“待活动结束”“数据口径”“核验通过”“订单支付成功”等正常语义被拆解为单字纵排。该问题不能通过把词语任意拆分来处理，应通过设置卡片最小宽度、改用横向滚动表格、在指定断点切换为单列布局，以及为中文标题设定语义化断行规则解决。

数据页截图还显示四张统计卡在窄宽度下仍被强制并排，造成金额、比率和说明的层级被挤压；信息应在中小屏切换为 2 列或 1 列，并保持数值与单位在同一行。空白截图显示存在只有分隔线而没有说明和下一步动作的空页面，需统一替换为包含原因、辅助说明与明确操作按钮的空状态。

登录页角色标题的正确规则：完整身份名必须保持为一个语义单元，允许在整个词组之间断行，但禁止把“平台运营人员”“主办方活动运营人员”“文旅业务指导人员”“现场协同人员”中的词语拆成单字或割裂“人员”。说明文案可按短语断行，例如“配置活动流程、账号权限、服务运营”保持一行或按逗号后的短语分行。

## 票务截图分段复核

票务相关卡片在极窄的内容列中被压缩为约 150–180px，导致“数据口径”“订单支付成功”“普通票、Coser票、学生票、现场票”等内容全部逐字断行。问题的根源是卡片网格缺少最小列宽及表格容器缺少横向滚动策略，不是中文文本需要“诗意换行”。修复原则是：数据卡片最小宽度不低于 220px；窄屏下优先改为单列卡片而非缩窄；表格类数据保持可横向滚动；数值、单位和核心状态标签使用 `whitespace-nowrap` 避免破坏核心信息。

## 现场核验截图分段复核

“核验通过”“与订单、实名和现场记录关联”“异常已登记并处置”等现场核验状态被压缩为竖排，说明现场数据卡在小视口没有重排。此类实时业务信息必须优先保证扫描、核验结果和异常状态的可读性：将现场统计改为 `minmax(160px, 1fr)` 的自适应网格，在小屏切换为 2 列；将“核验通过”“异常已登记并处置”保留为完整状态短语；描述文本仅能在短语边界换行，不能单字拆分。

## 现场核验截图底部复核

底部仍出现“已登记并处置”“支持按活动形成问题与操作记录”的逐字纵排。这证实该缺陷贯穿数据中心、现场核验和状态说明组件，并非局部文案问题。全站必须移除任何依赖极窄固定列的卡片布局；状态语义作为一个不可拆分的短语展示；当空间不足时，切换布局而不是继续压缩字体或逐字换行。
