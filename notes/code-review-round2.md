# 第二轮代码审查

## 摘要

本轮修改的目标是将资料查看类入口从说明性确认弹窗改为可连续推进的任务流，同时修复主体档案中的中文、机构名称和日期断行，并收紧后台视觉层级。整体评估为**可合并**：TypeScript 检查和生产构建均通过，核心路径已在浏览器中实际走通。

## 严重问题

未发现阻塞性安全、数据破坏或构建问题。本项目为静态前端原型，未接入后端接口或真实敏感数据；展示的联系方式和统一社会信用代码均为脱敏样例。

## 主要问题与处理

| 优先级 | 发现 | 本轮处理 |
|---|---|---|
| P1 | “查看记录”仅显示说明与确认，未进入真实业务上下文 | 已替换为统一的右侧任务抽屉：查看当前资料、补充或更新、提交并写入记录 |
| P1 | 主办方主体资料、机构名称、有效期和日期发生非语义断行 | 已通过不可拆分 token、表格最小宽度和横向滚动策略修复 |
| P2 | 通知列表仍使用独立的提示弹窗，与表格操作不一致 | 已接入同一套任务抽屉 |
| P2 | 侧栏收起控件和选中态视觉过重 | 已调整为图标式折叠、浅色选中态与细线标识 |

## 后续技术债

`Home.tsx` 仍是单文件原型，任务抽屉、通知中心、主办方主体档案、现场核验和角色审核均在同一文件。进入后端联调前建议拆出 `TaskDrawer`、`OrganizerProfile`、`NotificationPanel`、`ActivityRecord` 等组件，并将各类数据定义迁移为统一的 TypeScript domain model。当前不影响演示，但会影响多人并行开发和后续接口接入。

## 正向评价

任务抽屉保持了所有原入口的 `ActionButton` 调用形式，降低了改造对现有页面的回归风险；三语入口未被改动；断行修复通过布局与 token 规则处理，未用缩小字体掩盖问题。
