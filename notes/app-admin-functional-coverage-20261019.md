# 漫圈App与趣集后台对应及新增管理入口

本次依据八个正式功能组166张App页面，在**原后台**新增3个管理面并注册到现有导航；未重建App、未制造支付/用户数据、未更换Demo链接。界面动作保存、发布、撤回与校验可在Demo配置层运行，真实用户和资金动作必须由真实接口响应确认。

## 直接使用的入口

- **活动管理 → 进入档案 → 概况**：用户端发布/封面/分享与访问范围、活动准入规则/场次/有效期/版本、结束取消确认、资格与异议列表、发布审计。文旅只读，主办方不得做平台取消与资格撤销。
- **票务管理 / 活动档案 → 票务**：购票退票政策版本、订单/单票详情、渠道结果查询和异常登记、退款申诉办理、取消影响批次。金额采用分，批准仅转处理中，不等于到账；历史订单冻结快照不可被新规则改写。
- **平台运营 → 账号与主体 → 用户与账户**：脱敏账户、消费者实名复核/申诉、微信绑定/安全事件/个人二维码只读、协议隐私实名SDK关于版本、认证短信策略。Demo只允许合规和安全策略配置，不生成或审批真实用户；真实模式细权限必须来自服务端。
- **原角色服装道具与现场管理**：保留两级审核、最终有效资格、扫码/手动核验、已退款及未知状态不入场、一次核销、按活动隔离。

资料修改、收藏、想去、黑名单、清除缓存等为用户自助，不为这些制造人工审批。个人profile二维码与电子票核销码必须分开。

## 两端共同调用合同

沿用v1 `{code:0,message,data}`。非0、HTML、缺data、401、403、409、422、超时都不等于业务成功，失败不回落样例。活动作用域用真实activityId；敏感操作服务端执行RBAC和activityScopes。写入需要expectedVersion及审计，资金/资格/单票以服务端返回为权威。

- 活动：GET/PATCH `/activities/:id`；配置body `{action:'governance.<save|publish|withdraw|publishRule|end|cancel>',expectedVersion,governance}`；GET `audit-logs`、`eligibilities`、`appeals`；POST `eligibilities/:eligibilityId/revoke`。
- 政策：GET `/activities/:id/ticket-policies`、PUT `ticket-policies/:policyId`、POST `ticket-policies/:policyId/publish`；请求带expectedVersion。
- 交易：GET `/activities/:id/orders[/:orderId]`、POST `orders/:orderId/channel-refresh`、POST `orders/:orderId/reconciliation-issues`。
- 售后：GET `/activities/:id/refund-appeals`、POST `refund-appeals/:appealId/decisions`；GET `cancellation-refund-batches`。申诉审批必须已知金额/冻结政策/单票资格，不能重复办理处理中/已到账。
- 用户：GET `/platform/consumer-accounts[/:id]`；PUT `consumer-accounts/:id/status`；POST `consumer-accounts/:id/bindings/:bindingId/force-unbind`。
- 消费者实名：GET `/platform/consumer-kyc[/:id]`；POST `consumer-kyc/:id/decisions`。不能用主办方入驻或活动角色审批替代消费者实名。
- 合规：GET/POST/PUT `/platform/compliance-documents[/:id]`；POST `compliance-documents/:id/publish`；GET/PUT `/platform/consumer-security-policy`。
- 登录失效返回登录；错误对象保留status/requestId/retryable/fieldErrors。未收到真实服务端权限不放开消费者隐私/认证操作。

## 明确交付边界

这是两套原仓库的管理前端、合同与安全规则补齐。当前仓库后端仍是静态服务，缺少真正消费者/渠道/资格服务；新增合同不能作为接口已实现的证明。当前任务写入原Demo资源被拒绝，故代码同步不等于原Demo已发布。既有开发主分支不自动覆盖，以原修复分支/PR供团队合入。下面的清单表示设计功能对应的管理/配置位置，不表示166条真实跨端链路已运行。
