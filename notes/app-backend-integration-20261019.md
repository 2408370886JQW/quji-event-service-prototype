# 漫圈 App × 趣集后台规则对齐

本次在原仓库修正活动范围、最终审核资格、退款状态、核销与资金未知结果的安全边界。保持原页面、品牌、导航和历史本地数据；不新建用户模拟器，不新增微信或支付宝支付替代服务。停用未使用的旧 MobileClient 随机订单／支付成功／合成二维码路径，当前漫圈视觉与交互仍以 CoDesign 项目 730659968887344 为准。

## 同一业务对象

React 的 eventId 和 Vue 的 activityId 必须指向同一个后台活动 ID，不得按活动标题或位置推断。申报与资格同时绑定活动、参与人 userId/attendeeId、submissionId 和冻结 ruleVersion；订单、电子票与退款以 orderId/orderNo、ticketId、refundRequestId 关联。主办方只能处理服务端授权活动；文旅只读。前端筛选不是鉴权，后端还必须按会话逐请求检查权限与对象归属。

已知样例只属于 EVT-2026-0628。其他活动无数据时为空，不借用第一场活动订单、人员、材料或统计。保存明确属于其他活动的审核与退款记录时直接拒绝，不改绑；旧 localStorage 键继续保留，已知主活动历史结构仅限主活动使用。

## 审核先行

后台主办方初审不等于 App 可付款资格。App 只能认可最终有效资格；平台复核通过、绑定 ID 和冻结规则一致，且未撤销、未过期、未变更资料时才可以继续下单。先按同一对象取得最新资料，再比较规则版本，不能先筛选旧规则而忽略新版待审核资料。普通服装也需要明确资格和承诺，不通过票种名称绕过资格步骤。

现场核验检查当前活动、场次、付款状态、退款冻结和最终资格。未接入资格服务或查询失败时必须拦截，不能仅凭姓名、Coser 标签或本地审批结果伪造入场权限。扫码与手动核验使用同一条件，实名核对不等于核销。

## 退款与重复支付

批准退款只变为 processing，文案为“已同意退款 退款处理中”，不等于退款到账。submitting、processing、failed、unknown、appeal_pending 等状态保持所涉电子票冻结，不释放库存和限购名额。申诉通过也不代表到账。只有渠道权威成功结果才为 refunded；同一 ticketId 重复回执只释放一次，部分退款不影响未退其他票。缺电子票 ID 或渠道确认依据的旧 refunded 记录仍需核对，不能直接释放名额。

退款金额使用下单冻结规则和整数分，政策缺失、规则版本不明、金额未知、电子票已使用时不允许直接批准资金操作。禁止全活动硬编码 24 小时或一概不退的规则。后端需检查冻结规则、费用、币种、已退金额上限及重复申请，并在事务中处理库存／票状态与渠道幂等回执。

已有 paid、payment_pending 或 payment_unknown 订单不能重新发起扣款。只有服务端明确未扣款、原订单仍有效且资格有效的失败结果才可继续原订单。关闭后晚到扣款进入核对与原路退款，不直接生成电子票。回调去重、渠道签名与金额核对均属于真实后端责任。

## 接口约定与当前边界

沿用 Vue3 docs/API_CONTRACT.md 的数字响应：`{ "code": 0, "message": "ok", "data": {} }`。非成功 HTTP、非零 code、HTML、缺 data、查询失败均不得回落到 localStorage 或样例结果。

Vue3 `VITE_DATA_SOURCE=api` 使用原 API 接入层；未接入的本地写操作禁用，不能伪造成功。React 同一配置禁止本地样例登录与本地业务写入，提供统一请求校验层但不冒充完整 API 客户端。React 静态服务对未接入 `/api` 返回明确 501 JSON，而不是成功的 SPA HTML。配置 VITE_API_BASE_URL 时它是 API 根，例如 `/api`，请求路径从 `/activities/...` 开始，避免重复拼接 `/api/api`。

当前可访问仓库没有团队真实支付／退款服务或漫圈 App 源码，因此这次的类型、单元测试和构建通过，只证明当前源码规则和构建质量，不能证明 App、后台和资金渠道已联调上线。原站发布与 GitHub 同步是两件事；原网站资源在当前任务的附加被拒绝，不绕过权限，也不另建网站。
